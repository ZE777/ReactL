# 設計與開發交接流程 (Design-to-Dev Handoff Workflow)

本文件定義從設計稿到程式碼實作的標準交接流程，確保設計意圖準確落地、減少來回溝通成本，並建立可追溯的設計決策記錄。

## 1. 交接流程概覽

```
設計稿完成 → 設計審查 → 交接文件產出 → 開發認領 → 實作 → 設計驗收
   [設計師]     [團隊]      [設計師]       [工程師]   [工程師]   [設計師]
```

### 階段說明

| 階段 | 負責人 | 產出物 | 完成標準 |
|------|--------|--------|----------|
| 1. 設計審查 | 設計師 + 工程師 | 審查紀錄 | 工程師確認技術可行性，無重大疑問 |
| 2. 交接文件 | 設計師 | 元件規格書、狀態矩陣 | 所有元件的所有狀態都有定義 |
| 3. 開發實作 | 工程師 | 程式碼 | 視覺與互動符合設計規格 |
| 4. 設計驗收 | 設計師 | 驗收報告 | Pixel-level 對齊、互動行為正確 |

## 2. 元件規格書 (Component Specification)

每個新元件或元件修改，必須包含以下規格：

### 2.1 元件基本資訊

```markdown
## Button（按鈕）

### 元件對應
- 設計稿位置：[Figma 連結或頁面名稱]
- 程式碼元件：`/src/shared/ui/Button.tsx`
- 使用位置：全站通用

### Props 介面
| Prop | 類型 | 預設值 | 說明 |
|------|------|--------|------|
| variant | 'primary' \| 'secondary' \| 'ghost' \| 'destructive' | 'primary' | 按鈕樣式變體 |
| size | 'sm' \| 'md' \| 'lg' | 'md' | 按鈕尺寸 |
| disabled | boolean | false | 禁用狀態 |
| loading | boolean | false | 載入中狀態 |
| icon | ReactNode | — | 前置圖示 |
| fullWidth | boolean | false | 是否撐滿容器寬度 |
```

### 2.2 尺寸變體

```markdown
### 尺寸定義
| Size | 高度 | 內距 (px) | 字級 | 圖示尺寸 |
|------|------|-----------|------|----------|
| sm | 32px (h-8) | px-3 py-1.5 | text-body-sm (14px) | 16px |
| md | 40px (h-10) | px-4 py-2 | text-body (16px) | 20px |
| lg | 48px (h-12) | px-6 py-3 | text-body-lg (18px) | 24px |
```

## 3. 狀態矩陣 (State Matrix)

每個互動元件必須定義所有可能狀態的視覺呈現：

### 3.1 狀態矩陣範本

以 Button 為例：

| 狀態 | 背景色 | 文字色 | 邊框 | 陰影 | 游標 | 其他 |
|------|--------|--------|------|------|------|------|
| Default | `brand-primary-500` | `white` | none | `elevation-1` | `pointer` | — |
| Hover | `brand-primary-600` | `white` | none | `elevation-2` | `pointer` | 過渡 150ms |
| Active / Pressed | `brand-primary-700` | `white` | none | none | `pointer` | transform scale(0.98) |
| Focus | `brand-primary-500` | `white` | none | `elevation-1` | `pointer` | Focus ring 2px offset |
| Disabled | `neutral-200` | `neutral-400` | none | none | `not-allowed` | opacity 不變（靠色彩區分） |
| Loading | `brand-primary-500` | `white` | none | `elevation-1` | `wait` | 文字替換為 Spinner |

### 3.2 表單欄位狀態矩陣

| 狀態 | 邊框色 | 背景色 | 標籤色 | 輔助文字 |
|------|--------|--------|--------|----------|
| Default | `neutral-300` | `white` | `neutral-700` | `neutral-500` |
| Hover | `neutral-400` | `white` | `neutral-700` | `neutral-500` |
| Focus | `brand-primary-500` | `white` | `brand-primary-600` | `neutral-500` |
| Filled | `neutral-300` | `white` | `neutral-700` | `neutral-500` |
| Error | `status-error` | `status-error-light` | `status-error-dark` | 錯誤訊息（紅色） |
| Disabled | `neutral-200` | `neutral-50` | `neutral-400` | `neutral-400` |
| Read-only | `neutral-200` | `neutral-50` | `neutral-700` | — |

## 4. 間距標註規範 (Spacing Annotation)

### 4.1 標註原則

*   **使用 Token，不使用數值：** 標註「`spacing-4`」而非「16px」
*   **區分 Padding 與 Margin：** 明確標示元素的內距（padding）與外距（margin）
*   **標註層級：**
    *   元件內部間距（元件內各子元素之間）
    *   元件之間間距（同級元件之間的 gap）
    *   區塊間距（Section 之間的垂直距離）

### 4.2 間距標註範例

```
┌─────────────────────────────── Card ──────────────────────────────┐
│  padding: spacing-6 (24px)                                        │
│  ┌──────────────────────────────────────────────────────────────┐ │
│  │  [Image]  height: 200px, border-radius: rounded-lg          │ │
│  └──────────────────────────────────────────────────────────────┘ │
│  ↕ gap: spacing-4 (16px)                                         │
│  ┌──────────────────────────────────────────────────────────────┐ │
│  │  [Title]  text-h4, font-semibold, text-neutral-900          │ │
│  └──────────────────────────────────────────────────────────────┘ │
│  ↕ gap: spacing-2 (8px)                                          │
│  ┌──────────────────────────────────────────────────────────────┐ │
│  │  [Description]  text-body-sm, text-neutral-500, line-clamp-2│ │
│  └──────────────────────────────────────────────────────────────┘ │
│  ↕ gap: spacing-4 (16px)                                         │
│  ┌──────────────────────────────────────────────────────────────┐ │
│  │  [Price]  text-h3, font-bold     [Button]  variant=primary  │ │
│  │           text-brand-primary-600           size=sm           │ │
│  └──────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
 ↕ Cards 之間 gap: spacing-6 (24px)
```

## 5. 動畫規格 (Animation Specification)

### 5.1 動畫規格範本

```markdown
### Dropdown Menu — 展開動畫

| 屬性 | 值 |
|------|-----|
| 觸發時機 | 點擊觸發按鈕 |
| 動畫屬性 | opacity + transform (scaleY) |
| 起始狀態 | opacity: 0, scaleY: 0.95, transform-origin: top |
| 結束狀態 | opacity: 1, scaleY: 1 |
| 持續時間 | 150ms (--duration-fast) |
| 緩動函數 | ease-out (--easing-enter) |
| 延遲 | 0ms |
| 退出動畫 | 反向，100ms (--duration-instant) |
```

### 5.2 Tailwind 動畫對應

```js
// tailwind.config.js — theme.extend.keyframes & animation
keyframes: {
  'dropdown-in': {
    '0%': { opacity: '0', transform: 'scaleY(0.95)' },
    '100%': { opacity: '1', transform: 'scaleY(1)' },
  },
  'slide-in-right': {
    '0%': { transform: 'translateX(100%)' },
    '100%': { transform: 'translateX(0)' },
  },
  'fade-in': {
    '0%': { opacity: '0' },
    '100%': { opacity: '1' },
  },
},
animation: {
  'dropdown-in': 'dropdown-in 150ms ease-out',
  'slide-in-right': 'slide-in-right 250ms ease-out',
  'fade-in': 'fade-in 200ms ease-out',
}
```

## 6. 邊界案例清單 (Edge Cases Checklist)

每個元件的交接文件必須涵蓋以下邊界案例：

### 6.1 文字內容

| 案例 | 處理方式 | CSS 實作 |
|------|----------|----------|
| 文字過長（單行） | 截斷 + 省略號 | `truncate` (Tailwind) |
| 文字過長（多行） | 限制行數 + 省略號 | `line-clamp-2` / `line-clamp-3` |
| 文字過長（不可截斷） | 允許換行 | `break-words` |
| 文字過長 + 需要完整內容 | 截斷 + Tooltip 顯示完整 | `truncate` + Tooltip on hover |
| 空文字 | 顯示 placeholder 或 dash | `{text || '—'}` |
| 極長單字（如 URL） | 強制斷行 | `break-all` |

### 6.2 圖片內容

| 案例 | 處理方式 |
|------|----------|
| 圖片載入中 | 顯示 Skeleton placeholder |
| 圖片載入失敗 | 顯示 Fallback 圖片（品牌 Logo 或通用 placeholder） |
| 圖片比例不符容器 | 使用 `object-cover` 裁切或 `object-contain` 留白 |
| 無圖片 | 顯示預設 placeholder（圖示 + 淺灰背景） |

### 6.3 數據量

| 案例 | 處理方式 |
|------|----------|
| 列表 0 筆 | 顯示空狀態（見 `13_使用者流程與互動模式規範.md`） |
| 列表 1 筆 | 正常顯示，不可出現佈局錯位 |
| 列表超過 100 筆 | 使用分頁或虛擬列表 |
| 數字過大（如 ¥99,999,999） | 確認欄位寬度足夠或使用縮寫（如 9,999 萬） |
| 數字為 0 | 顯示 `0` 而非空白 |
| 數字為 null/undefined | 顯示 `—` 或 `N/A` |

## 7. 設計驗收標準 (Design QA Criteria)

### 7.1 視覺驗收

- [ ] 色彩完全對應 Design Token（無任意色號）
- [ ] 字型、字級、字重對應設計規格
- [ ] 間距使用 Token 對應值（±2px 容許誤差）
- [ ] 圓角、陰影對應 Token
- [ ] 圖示尺寸與 Stroke Width 正確

### 7.2 互動驗收

- [ ] 所有狀態（Hover / Active / Focus / Disabled / Error / Loading）呈現正確
- [ ] 過渡動畫時間與緩動函數正確
- [ ] 按鈕 Loading 期間不可重複點擊
- [ ] 表單驗證在正確時機觸發
- [ ] Toast 出現位置、持續時間、堆疊行為正確

### 7.3 響應式驗收

- [ ] 375px / 768px / 1024px / 1280px 四個關鍵斷點佈局正確
- [ ] 觸控目標 ≥ 44×44px（手機端）
- [ ] 文字放大 200% 後佈局不破裂

### 7.4 無障礙驗收

- [ ] 所有互動元素可透過鍵盤操作
- [ ] Focus 順序合理且 Focus 樣式可見
- [ ] 螢幕閱讀器可正確解讀內容與狀態
- [ ] 色彩對比度達 AA 標準
