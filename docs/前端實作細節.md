## A. 前台 prompt-studio-web（Next.js 16）

公開展示與訪客聊天網站。App Router、以 Server Component 為主、聊天頁為 Client 重邏輯。部署於 `/app` 子路徑（`basePath`），`output: "standalone"` 供 PM2 託管。

### A1. 路由與 Server / Client 切分

`src/app/` 採 App Router 慣例：

| 路由 | 檔案 | 型態 | 說明 |
|------|------|------|------|
| `/` | `page.tsx` | Server | Landing（Hero / Features / TechStack）|
| `/about` | `about/page.tsx` | Server | 作品集說明、模組架構 |
| `/login` | `login/page.tsx` | Client | 後台登入表單，成功後導向後台 |
| `/chat` | `chat/page.tsx` + `chat/ChatClient.tsx` | Server 殼 + Client | `page.tsx` 以 `<Suspense>` 包住 `ChatClient`（因其使用 `useSearchParams()`）|
| `/share/[slug]` | `share/[slug]/page.tsx` | Server | 唯讀分享對話，`generateMetadata()` 動態產生 SEO |

- **Root layout**（`app/layout.tsx`）：title template `'%s | Prompt Studio'`、OpenGraph、`next/font/google`（Geist Sans/Mono）、`<ThemeScript>` 防深色模式閃白、`<html suppressHydrationWarning>`。
- **錯誤邊界**：`app/error.tsx`（Client，`error` / `reset`）、`app/not-found.tsx`。
- **Next.js 16 動態參數**：`params: Promise<{ slug }>`（需 `await`）。
- **切分原則**：Landing / About / Share 走 Server（靜態 + SSR metadata 新鮮度）；Chat 把所有互動邏輯下放至 `ChatClient`（Client）。`Markdown` 本身為 Server Component，僅把需要互動的子元件（複製、燈箱、Mermaid）做成 Client。

> ⚠️ 此版 Next.js 與訓練資料可能有出入，動程式碼前先讀 `node_modules/next/dist/docs/`（見 `prompt-studio-web/AGENTS.md`）。

### A2. 資料層與 SSE 串流

集中於 `src/lib/api.ts`：

```ts
const BASE_URL = process.env.NEXT_PUBLIC_API_URL ?? 'https://localhost:44345/api/v1'
// apiFetch<T>()：10s AbortSignal.timeout()，可合併呼叫端 signal；非 2xx 拋錯
// 方法：api.get / post / patch / delete
```

- **認證**：登入由後端寫入 **HttpOnly Cookie**，前端不持有 token；登入後 `window.location.href` 導向後台。
- **共通 headers**：`Content-Type: application/json`、`ngrok-skip-browser-warning: true`、`X-Access-Code`（存取碼）、`X-Chat-Session`（瀏覽器層識別）。
- **公開端點**（免登入）：`GET /public/personas`、`GET /public/access/status`、`GET /public/chat/history`、`POST /public/chat/stream`（SSE）、`GET /conversations/share/{slug}`。

**SSE 串流**（`ChatClient.tsx` 的 `handleSend()`）以 `fetch` + `ReadableStream` 手動解析（非 `EventSource`，便於攜帶 POST body 與處理多種 chunk）：

```ts
const res = await fetch(`${API_URL}/public/chat/stream`, {
  method: 'POST',
  body: JSON.stringify({ personaId, modelType, messages: history, userMessage: text }),
  signal: ctrl.signal,           // AbortController → 使用者「停止」按鈕
})
const reader = res.body.getReader()
// 逐塊解析 "data: {...}"；chunk 類型：delta / truncated / quota_exceeded / rate_limit / error
```

- `modelType` 以該角色設定為準（`selectedPersona.modelType`），fallback `groq:llama-3.3-70b-versatile`。
- `abortRef` 保存當前 `AbortController`；切換角色 / 卸載時中止，避免浪費上游費用。
- 前台公開聊天**不寫入後端 DB**（歷史由前端帶入），訪客紀錄另由後端寫 `PublicChatLogs` 供後台監控。

### A3. 存取碼與公開聊天流程

支援邀請制（可由後台開關）：

1. `fetchAccessStatus(code)` 取得 `PublicAccessStatus`（`requireAccessCode` / `valid` / `dailyTokenLimit` / `usedToday` / `remaining` / `logRetentionDays`）。
2. 需存取碼但無有效碼 → 顯示輸入閘門。
3. 存取碼存於 `localStorage['ps_access_code']`；網址 `?code=xyz` 首訪自動寫入。
4. 所有公開 API 帶 `X-Access-Code` 供配額計算。
5. **Chat session**：`getChatSessionId()` 產生一次性 UUID 存 `localStorage['ps_chat_session']`，以 `X-Chat-Session` 送出，讓後端把同一訪客的訊息歸群（與存取碼不同：碼＝跨裝置身分，session＝單瀏覽器 fallback）。

聊天頁狀態全部以 React hooks 就地管理（`personas` / `selectedPersona` / `messages` / `isStreaming` / `accessStatus` …），**無全域狀態庫**。

### A4. Markdown 渲染管線

核心 `src/components/ui/Markdown.tsx`（前台與後台 `MarkdownComponents.tsx` 同一套堆疊）：

```ts
remarkPlugins={[remarkGfm, remarkMath, remarkEmoji]}
rehypePlugins={[rehypeRaw, [rehypeSanitize, sanitizeSchema], rehypeKatex, rehypeHighlight]}
```

| 能力 | 套件 |
|------|------|
| 表格 / 刪除線 / 任務清單 / 註腳 | remark-gfm |
| 數學公式 `$...$` / `$$...$$` | remark-math → rehype-katex |
| Emoji shortcode `:smile:` | remark-emoji |
| 程式碼高亮 | rehype-highlight + highlight.js |
| 受控原生 HTML | rehype-raw + rehype-sanitize |

- **沙箱**（`markdownSanitize.ts`）：白名單 schema，放行 `<details>/<summary>`、KaTeX / highlight.js / GFM 所需 `className`/`id`；封鎖 `<script>`、`on*`、`style`、任意 `<iframe>`。
- **自訂元件映射**：`CodeBlock`（語言標籤 + 行號 + 複製）、`Mermaid`（偵測 ` ```mermaid `、下載 SVG）、`MarkdownImage`（lazy + 燈箱）、`MarkdownTable`（hover 複製 TSV）、`MarkdownMedia`（裸 URL 自動轉 YouTube / Vimeo `<iframe>` 或原生 `<video>/<audio>`）。
- 互動子元件為 Client Component，外層 `Markdown` 維持 Server。

### A5. 樣式、深色模式與動畫

- **Tailwind 4**：`app/globals.css` 以 `@import "tailwindcss"` 為單一入口，無 `tailwind.config.js`，主題用 `@theme {}` CSS 變數；`postcss.config.mjs` 掛 `@tailwindcss/postcss`。
- **深色模式**：class-based，`@custom-variant dark (&:where(.dark, .dark *))`；`ThemeScript` 在 hydration 前依 `localStorage.theme` 或 `prefers-color-scheme` 決定，避免閃白；`Header` 切換 `<html>.dark` 並持久化。
- **class 合併**：`cn()`（`src/lib/cn.ts`）＝ `clsx` + `tailwind-merge`。
- **動畫**：Framer Motion，純捲動觸發（`whileInView`）的淡入 / stagger（Hero / Features / TechStack），無複雜手勢。
- **元件**：手刻於 `components/ui`（`Button` 多 variant）、`components/layout`（`Header` sticky + 手機選單、`Footer`）、`components/landing`（三段式 section）。無第三方 UI 框架。

### A6. 型別與設定

- **型別**（`src/types/index.ts`）：`Message`（含 `truncated?`）、`Persona`（含 `modelType?`）、`SharedConversation`、`ApiError`；`PublicAccessStatus` 定義於 `api.ts`。
- **`next.config.ts`**：`basePath: "/app"`、`output: "standalone"`；`NEXT_PUBLIC_IGNORE_TLS=1` 時放行 localhost 自簽憑證。
- **`tsconfig.json`**：strict、path alias `@/* → ./src/*`。
- **ESLint**：`eslint-config-next`（core-web-vitals + typescript）。
- **環境變數**：`NEXT_PUBLIC_API_URL`（須含 `/api/v1`）、`NEXT_PUBLIC_ADMIN_URL`。

## B. 後台 prompt-studio-admin（Vite + React）

管理介面：角色 / Prompt / 對話 / Bot / 存取碼 / 監控 / 統計 / AI 金鑰。部署於 `/admin/` 子路徑，class-based 深色模式，自建 Design Token 與 UI 元件庫。

### B1. 路由與守衛

`src/main.tsx` 以 `createBrowserRouter()` 建構，`basename` 取自 `import.meta.env.BASE_URL`（對應 `/admin/`）。

```
/login                              → LoginPage（公開）
/ (PrivateRoute)
  ├─ /change-password               → ForcePasswordChangePage（首登強制改密）
  └─ / (AdminLayout)
       ├─ /chat、/chat/:id          ├─ /conversations  ├─ /personas、/personas/:id/versions
       ├─ /prompts  ├─ /bots        ├─ /access-codes   ├─ /monitor
       ├─ /public-chat-monitor      ├─ /stats          ├─ /settings、/settings/ai-keys
```

- **PrivateRoute**（`components/PrivateRoute.tsx`）：檢查 `localStorage.token` 與 `expiresAt`，逾期或缺失導向 `/login`。
- **AdminLayout**（`layouts/AdminLayout.tsx`）：
  - `mustChangePassword` → 強制導向 `/change-password`。
  - **最小金鑰閘門**：若使用者無任何自有 AI 金鑰，鎖住除 `/settings` 與 `/settings/ai-keys` 外的所有頁。
  - 以 regex 對應動態路由產生頁標題；左側對話清單側欄；手機 hamburger。
- **登出**：`App.tsx` 全域監聽 `auth:logout`（401 觸發）；並依 `expiresAt` 設定到期自動登出計時器。

### B2. API 層（axios 攔截器）

axios 實例 `src/lib/api.ts`，端點依資源拆於 `src/api/*.ts`。

```ts
const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,   // 例 https://localhost:44345/api/v1
  timeout: 30000,
  headers: { 'ngrok-skip-browser-warning': 'true' },
})
```

- **Request 攔截器**：自動注入 `Authorization: Bearer ${localStorage.token}`。
- **Response 攔截器**（全域 Toast）：401 清 token + 發 `auth:logout`；403 / 429 / 5xx / 網路 / 逾時各對應提示。**400 / 404 / 409 / 422 不攔**，交由元件就地顯示行內錯誤。
- **解包**：`unwrap<T>(res)` 取 `res.data.data`（後端統一 `ApiResponse<T> = { success, data, message? }`）。
- **跨 React 樹發 Toast**：`src/lib/toastEmitter.ts` 模組層 emitter，讓攔截器（在 React 外）也能推 Toast。
- **端點檔**：`personas.ts` / `prompts.ts`（tag 字串切分）/ `aiKeys.ts` / `bots.ts`（token 遮罩）/ `accessCodes.ts` / `publicChatMonitor.ts`。資料清洗（如 `promptSections` 後端可能回 JSON 字串 → `parsePersonaSections()`）集中在此層。

### B3. 伺服器狀態（React Query）

`main.tsx` 的 `QueryClient` 預設 `retry: false`、`refetchOnWindowFocus: false`。

- **Query keys**：`['conversations']`、`['conversation', id]`、`['personas']`、`['persona-detail', id]`、`['personas-list']`（`staleTime` 5 分鐘）、`['prompts']`、`['ai-keys']`、`['profile']`。
- **模式**：相同 key 自動去重共享（AdminLayout 與 ChatPage 共用 `['conversation', id]`）；`enabled` 條件查詢（角色選單開啟才抓）；mutation 於 `onSuccess` 失效相關 key。

### B4. 客戶端狀態（Zustand + Context）

- **Zustand**（`store/conversationStore.ts`）：`persist` 至 `localStorage['conversation-store']`；持有 `conversations` / `activeId` 與 CRUD actions。
- **ThemeContext**：`'light' | 'dark'` 存 `localStorage['theme']`，切 `<html>.dark`；`useTheme()`。
- **ToastContext**：success / error / warning / info，8 秒自動關閉，右下固定；`useToast().push(type, msg)`，與上述 `toastEmitter` 串接。

### B5. 表單（react-hook-form）

- **共用工具**（`src/lib/form.ts`）：`noSpace(register)` 即時去空白（token / 密碼類）；`useNoSpace()` 另回傳「不可輸入空白」提示。
- **錯誤分流**：欄位錯誤 `errors.field?.message`；API 級錯誤掛 `errors.root`（401/403）；400/404/409/422 對應欄位錯誤。
- **PersonaForm**：`useWatch()` 即時依賴欄位 + `EmojiPicker` + `PromptBuilder`（role / background / task / format / constraints / examples 結構化組裝，驗證必填段落後組出最終 system prompt）。

### B6. 設計系統（Design Token + UI 元件庫）

- **Token 層**（`src/tokens/colors.ts`）：色彩語意 `violet | slate | green | red | amber | blue`，三組對映 `softColorMap`（Tag）、`badgeColorMap`（Badge）、`iconColorMap`（IconButton）。
- **Tailwind 4**（`src/index.css`）：`@import "tailwindcss"; @plugin "@tailwindcss/typography"; @variant dark (&:is(.dark *));`，無 config 檔，`@tailwindcss/vite` 自動處理；自訂細捲軸、`page-enter/exit` 轉場。
- **UI 元件庫**（`components/ui/`）：`Button`（primary / secondary / ghost / danger / danger-ghost / blue + loading）、`Input` / `Textarea`（label / error / hint）、`Card`、`Badge`、`Tag`、`Modal`、`Spinner`、`PageLoading`、`PageError`、`IconButton`、`DropdownSelect`、`FilterPill`、`SegmentedControl`、`EmptyState`、`MarkdownComponents`。
- **領域元件**（`components/persona/`）：`PersonaForm`、`PersonaListPanel`、`PromptBuilder`。
- **Markdown**：與前台同套 remark/rehype 堆疊（GFM / KaTeX / Mermaid / highlight + rehype-sanitize）。

### B7. 型別與設定

- **型別**（`src/types/`）：`api.ts`、`persona.ts`（`Persona` / `PersonaFormData` / `PersonaVersion` / `PromptSections`）、`prompt.ts`、`ai.ts`（`AiProvider` / `AiKey`）、`bot.ts`、`accessCode.ts`、`publicChatMonitor.ts`。
- **`vite.config.ts`**：`base: '/admin/'`、plugins `react()` + `tailwindcss()`、port 取自 `VITE_UI_URL`。
- **`tsconfig`**：`ES2023` / `ESNext` / `react-jsx`，嚴格檢查（`noUnusedLocals` 等）。
- **ESLint 10 flat config**：js + tseslint + react-hooks + react-refresh。
- **環境變數**：`VITE_API_BASE_URL`（含 `/api/v1`）、`VITE_UI_URL`、`VITE_PUBLIC_WEB_URL`。

## C. 兩端共通約定

| 面向 | 前台 web | 後台 admin |
|------|----------|-----------|
| 框架 | Next.js 16 App Router | Vite 8 + React Router 7 |
| 認證載體 | HttpOnly Cookie（後端寫入）| `Authorization: Bearer`（localStorage token）|
| 伺服器狀態 | 元件就地 `useEffect` | @tanstack/react-query |
| 全域狀態 | 無 | Zustand + Context |
| 子路徑 | `/app`（`basePath`）| `/admin/`（`base`）|
| 深色模式 | class-based `.dark` + `ThemeScript` | class-based `.dark` + `ThemeContext` |
| Markdown | 同一套 remark/rehype + rehype-sanitize 沙箱 | 同左 |
| 錯誤分工 | API 拋錯就地顯示 | 攔截器全域 Toast（401/403/429/5xx）＋元件行內（4xx 驗證）|
| ngrok | `ngrok-skip-browser-warning` header | 同左 |

- **API 路由前綴一致**：兩端皆指向後端 `/api/v1`（前台另用 `/public/*` 與 `/webhooks/*` 不在此前綴）。
- **角色模型權威在後端**：前台公開聊天的模型以各 `Persona.ModelType` 為準（見 `database-schema-and-dataflow.md`）。
- **維護**：新增頁面 / 端點 / 共用元件 / 設計 Token / 環境變數時，請同步更新本文件與對應 `README.md`。
