# 微互動與體驗指南 (Micro-Interactions & UX)

如何在網頁中加入生動的互動與動畫，但卻不吃掉瀏覽器效能，並且不讓程式碼過度複雜化？這份文件提供了最佳實踐方案。

## 1. 原則：保持簡單，避免過度設計
*   **CSS 優先原則：** 如果能用 CSS `transition` 或 `animation` 解決的動態效果（如 Hover、淡入淡出、按鈕點擊縮放），**絕對不要**動用 JavaScript。這能帶來最好的效能 (GPU 加速)。
*   **專注於 `transform` 與 `opacity`：** 動畫變更這兩個屬性不會觸發瀏覽器的 Reflow（版面重排）與 Repaint（重繪）。**嚴禁**使用動畫頻繁改變 `width`, `height`, `margin`, `top/left`。

## 2. 骨架屏 (Skeleton Screens) 的運用
比起一直轉圈圈 (Spinner) 讓用戶有「等待感」，骨架屏是在資料回傳前預先顯示排版輪廓。
*   在非同步請求發出時，先渲染具有漸層閃爍 (Shimmer effect) 的灰色區塊代替圖片和文字結構。這可以顯著降低使用者的等待焦慮感，確保畫面不會重整跳動 (Prevent Layout Shift)。

## 3. 基礎與易用的小型動畫
若使用 React 或 Vue，不需要引入過於厚重的全能型動畫引擎。
*   如果是 React，推薦使用 **Framer Motion** 的基礎功能，專注於頁面切換 (Page Transitions) 與列表項目的出現 (Enter/Exit 動畫) 即可，不要用它做誇張的 3D 物理碰撞。
*   設定全局的動畫漸變曲線：建議在 CSS Variables 定義好 `ease-in-out` 的統一參數，例如：`--transition-smooth: all 0.3s cubic-bezier(0.25, 0.8, 0.25, 1);`，所有元件引用，維持品牌視覺體驗的一致性。

## 4. 雙系統動畫策略（Admin vs 使用者端）

同一個產品的兩個系統，動畫策略應有明確差異：

| 系統 | 動畫強度 | 工具 | 原則 |
|------|---------|------|------|
| **後台 Admin**（Vite）| Subtle | Tailwind `transition-*` | 功能性過渡為主，不分散管理者注意力 |
| **使用者端 Web**（Next.js）| Rich | Framer Motion + Tailwind | 頁面進場、元件出現、hover 浮起、scroll 觸發 |

### Admin 動畫只做以下幾種
- `hover:bg-*`、`transition-colors`：選單、按鈕、卡片 hover
- `animate-pulse`：Skeleton loading
- `transition-all duration-150`：表單 focus ring 出現

### 使用者端 Web 建議的 Framer Motion 使用場景
- 頁面進場：`initial={{ opacity: 0, y: 8 }}` → `animate={{ opacity: 1, y: 0 }}`
- 列表項目出現：`staggerChildren` 錯開進場
- 卡片 hover 浮起：`whileHover={{ y: -2, boxShadow }}`
- AI 回應逐字出現：streaming 搭配文字動畫

## 5. 視覺設計規範（Untitled UI Dark 風格）

本專案 Admin 採用 Untitled UI Dark 設計語言：

```
背景層級（由深到淺）：
  Page bg：zinc-950 (#09090b)
  Surface：zinc-900
  Input/Card inner：zinc-800
  Hover：zinc-800/50

文字層級：
  Primary：zinc-100
  Secondary：zinc-400
  Placeholder：zinc-500
  Disabled：zinc-600

邊框：
  一般：zinc-800
  表單欄位：zinc-700（focus 時變 violet-500）
  分隔線：zinc-800 dashed

主色：violet-600（hover: violet-500）
危險色：red-500
成功色：emerald-500
```

**表單排版規則（Untitled UI 水平式）：**
- label 區塊固定寬度（`w-32`），靠左
- input 區塊 `flex-1`，靠右
- 各欄位用 `border-b border-dashed border-zinc-800` 分隔

## 6. 表單防護與狀態回饋機制 (Form Interaction & Prevention)
*   **表單驗證攔截 (Validation Disabled)：**
    *   在表單必填欄位未完備或格式有誤時，應將提交按鈕設為「灰色且不可點擊 (`disabled`)」，直到通過所有驗證才顯示彩色活動狀態。
    *   **必須搭配即時驗證 (Inline Validation)：** 單純禁用按鈕可能導致使用者困惑，需在欄位旁即時顯示錯誤提示（如焦點移除或輸入時防呆），導引用戶快速修正錯誤。
*   **避免重複提交 (Prevent Double Submission / Loading Disabled)：**
    *   一旦使用者點擊送出並觸發 API 請求瞬間，**必須立刻**將按鈕切換至 `disabled` 狀態，避免因網路延遲產生連點行為（如重複下單或連發資料）。
    *   **加上過程回饋：** 在 `disabled` 狀態期間，應於按鈕顯示 Loading spinner 或變更文字為「處理中...」，並在 API 請求完成（成功或失敗）後才解除禁用狀態。
*   **Toast (吐司通知)：** 出現在螢幕角落的非阻擋式提示（例如「已加入購物車」、「儲存成功」），它應該在 3 到 5 秒後自動淡出，不阻礙使用者的下一步操作。
