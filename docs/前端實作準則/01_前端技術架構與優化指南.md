# 前端專案啟動：技術架構與優化指南 (Frontend Technical Guidelines)

作為專案初期的技術雷達，這份文件列出了在您啟動任何新前端專案時，必須進行評估的「技術大項」。請在確定架構或寫下第一行程式碼前，與您的 AI 導師或團隊走過這份檢核表。

## 1. 實作邊界與需求收斂 (Implementation Boundaries)
在動工前，最危險的事情就是「什麼都想做」。必須明確定義以下邊界：
*   **MVP (Minimum Viable Product) 範圍：** 釐清「必須有 (Must-have)」與「有很好但非必要 (Nice-to-have)」的功能。將非核心的炫技動畫或次要流程延後到 Phase 2。
*   **技術妥協與限制：** 有些功能若透過前端實作成本極高（例如：前端處理巨量資料過濾），應主動提出將邊界推至後端 (BFF 或 API) 處理。
*   **瀏覽器與裝置支援度：** 明確定義最低支援的瀏覽器版本（如：不支援 IE11、Safari 至少支援到 v14），這將直接影響 CSS 特性與 Polyfill 的選擇。

## 2. 搜尋引擎優化與語意化 (SEO & Semantic HTML)
SEO 不只是行銷團隊的事，前端架構在第一天就決定了搜尋引擎的青睞度：
*   **渲染策略 (Rendering Strategy) — 本專案採雙軌制：**
    *   **對外公開網站 → Next.js (App Router, SSR/SSG)。** 為了被搜尋引擎完整收錄，所有面向客戶的頁面必須走伺服器端渲染。
    *   **對內管理後台 → React + Vite (純 SPA)。** 不需要被爬蟲索引，採 Vite 打包靜態檔以最大化渲染效率與 HMR 開發體驗。
    *   詳細路由與框架選型守則見 [SKILL_雙軌路由與SSR切分](../../skills/SKILL_雙軌路由與SSR切分.md)。
*   **TDK 與 Open Graph (OG)：** 必須預留給各頁面設定動態 Title, Description, Keywords 以及社群分享縮圖 (og:image) 的機制。
*   **語意化標籤 與 a11y：** 摒棄「全盤 `<div>`」的寫法。正確使用 `<header>`, `<main>`, `<article>`, `<nav>`，並在需要時補上 ARIA Attributes 以提升無障礙體驗。

## 3. UI/UX 體驗與介面韌性 (UI/UX & Resilience)
優秀的前端不只要好看，更要在「狀態變換」與「網路不穩定」時保持優雅：
*   **骨架屏與載入狀態 (Skeleton & Loading)：** 避免資料尚未取回時畫面一片空白或嚴重跳動 (Layout Shift)，應設計統一的 Loading 策略。
*   **錯誤邊界與降級體驗 (Error Boundaries & Fallback)：** 當 API 報錯或某個元件崩潰時，不能讓整個網站白畫面。必須設計全域及局部的 Error Handling UI。
*   **微互動 (Micro-interactions)：** 按鈕點擊、表單驗證成功/失敗，必須提供即時的視覺反饋。
*   **Design Tokens 制：** 絕對禁止在程式碼中四處 hardcode 色碼 (`#FF0000`) 或間距 (`16px`)。應在專案初期建立好 CSS Variables (或 Tailwind config) 的設計系統。

## 4. 網頁效能優化 (Web Performance)
效能是留住用戶的底線，需在架構期就納入考量 (參考 Web Vitals 核心指標)：
*   **LCP (最大內容繪製)：** 首圖或核心焦點不能被龐大的 JS 阻塞載入。重要圖片預先載入 (`<link rel="preload">`)。
*   **CLS (累計版面配置轉移)：** 所有圖片與動態廣告區塊，必須預先設定好 `width` 與 `height`，防止圖片載入後將文字往下擠。
*   **Bundle Size 瘦身：** 採用動態載入 (Code Splitting / Dynamic Import) 將不常看的頁面（如：設定頁）打包成獨立檔案。
*   **靜態資源最佳化：** 圖片自動轉換為 WebP/AVIF 格式，小圖示統一使用 SVG 或 Icon Font。

## 5. 資料流與 API 串接管理 (Data Fetching & State)
*   **全域與區域狀態拆分：** 不要把所有變數都塞進 Redux 或 Pinia。UI 開關（如 Modal 開關）放區域狀態 (useState)，跨頁面共用資料才放入全域狀態。
*   **伺服器狀態快取：** 導入如 React Query, SWR 或 RTK Query 的快取庫，幫助接管複雜的 API 重試、快取、與畫面焦點切換時的自動更新。
*   **攔截器 (Interceptors)：** 在發送請求前自動帶入 Token，在收到 401 錯誤時自動觸發 Token Refresh 或導向登入頁。

## 6. 前端資安防護 (Security)
*   **XSS 防禦：** 框架 (Vue/React) 已自帶部分防護，但若使用 `dangerouslySetInnerHTML` 或 `v-html` 渲染外部文本時，務必強制搭配 `DOMPurify` 進行消毒。
*   **Token 存放安全：** 避免將高敏感的 JWT Access Token 存在輕易被讀取的 `localStorage` 中，評估使用 **HttpOnly Cookie** 存放的可行性。
*   **敏感資訊隔離：** 確保所有的 API Secrets 都不會因為錯誤的 `.env` 命名方式（如不小心加上 `VITE_` 或 `NEXT_PUBLIC_`）而曝露在網頁原始碼中。
