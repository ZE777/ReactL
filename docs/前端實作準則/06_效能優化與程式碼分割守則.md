# 效能優化與程式碼分割守則 (Performance & Code Splitting Guide)

前端效能直接決定了轉換率，這份準則定義了程式碼層面必須強制執行的效能優化手段。

## 1. 程式碼分割 (Code Splitting)
不要讓使用者在進首頁時，就把整個系統的幾十個頁面程式碼都下載下來。
*   **路由層級分割 (Route-based Splitting)：** 必須使用 `React.lazy()` 搭配 `Suspense` (或是 Vue Router 的動態載入 `() => import(...)`)。確保使用者進到 `/dashboard` 才會載入 dashboard 的 JS 檔案。
*   **大型套件延遲載入 (Component-based Splitting)：** 如果某個頁面有一個很肥的第三方套件（例如：匯出 Excel 的 `xlsx` 套件、或是大型圖表庫如 `ECharts`），絕不可以直接預設 `import`，必須在使用者點擊按鈕或滑到該區塊時，再做**動態載入 (Dynamic Import)**。

## 2. 避免無效渲染 (Preventing Re-renders)
在 React 中，父元件重新渲染，子元件就會無條件跟著渲染。我們必須斬斷這層不必要的牽連：
*   **MemoIZATION 策略：** 高頻繁觸發的表單元件，或是極度複雜的資料表元件，必須包上 `React.memo`。
*   **穩定的 Reference：** 傳入子元件的 functon (如 `onClick`) 必須用 `useCallback` 記憶；耗時沉重的陣列計算結果必須用 `useMemo` 記憶，以免每次渲染皆產生新的記憶體位置而打破 `React.memo` 的防護。

## 3. DOM 節點效能 (Long Lists & Virtualization)
*   **虛擬列表 (Virtual List)：** 如果畫面上要顯示超過 50 筆以上的名單或無限滾動清單，**絕對禁止**直接用 `.map()` 渲染所有 DOM。請務必引入 `react-window` 或 `react-virtuoso` 進行虛擬渲染（只渲染目前眼睛看得到的 10 到 15 個節點）。

## 4. Tree Shaking 與 Bundle Size 檢測
*   **精準載入依賴：** 引入函式庫時，禁止全盤載入（如 `import _ from 'lodash'`），應具名導入（如 `import { debounce } from 'lodash'`）以支援 Tree Shaking。
*   **定期體檢：** 部署流程必須結合 `webpack-bundle-analyzer` 或 `rollup-plugin-visualizer`，一旦發現單個 chunk 檔案超過 500KB，就必須提出拆分計畫。
