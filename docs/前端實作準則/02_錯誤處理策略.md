# 錯誤處理策略 (Error Handling Strategy)

本指南旨在為前端專案建立標準化的「錯誤攔截與錯誤呈現」機制，確保在網路不穩、API 報錯或元件渲染異常時，系統能展現高度的「韌性 (Resilience)」且不讓使用者看見白畫面。

## 1. 錯誤的分類與處理層級

前端面臨的錯誤主要分為三大類，處理層級各有不同：
*   **執行期渲染錯誤 (Runtime/Rendering Errors)：** 元件在渲染時因為資料為 undefined 導致崩潰。 -> **由 Error Boundaries (錯誤邊界) 處理。**
*   **API 網路請求錯誤 (Network/HTTP Errors)：** 後端回傳 4xx 或 5xx 錯誤。 -> **由 API Interceptors (攔截器) 全域處理與區域 Catch 處理。**
*   **預期內業務邏輯錯誤 (Business Logic Errors)：** 例如庫存不足、密碼錯誤。 -> **由 UI 元件捕捉並顯示 Toast/表單提示。**

## 2. API 攔截器 (Axios Interceptors) 實作規範

所有的外部請求必須經過統一的實體 (Instance)，不可在元件中隨處宣告 `fetch`。
*   **Request Interceptor (請求攔截)：** 負責將 Token 動態塞入 Header。
*   **Response Interceptor (回應攔截)：** 
    *   `401 Unauthorized`：觸發 Token Refresh 流程（完整實作詳見 `SKILL_API層與攔截快取.md`）。
        *   **Token Refresh 競態條件處理：** 當多個並發請求同時遇到 401 時，僅第一個請求觸發 Refresh，其餘請求進入 Promise Queue 等待。Refresh 成功後，所有等待中的請求以新 Token 重新發送（Replay）；Refresh 失敗則統一清空 Token 並導回登入頁。
        *   **禁止直接 `window.location.href = '/login'`：** 在未嘗試 Refresh 前，不可直接跳轉登入頁，否則使用者在正常操作中會因 Token 自然過期而被強制登出，體驗極差。
    *   `403 Forbidden`：導向權限不足的提示頁面。
    *   `500 Internal Server Error`：觸發全域的 Toast 通知「系統遭遇異常，請稍後再試」。

## 3. Error Boundaries (錯誤邊界設計：白畫面的終極解法)

前端專案嚴禁因為單一子元件的邏輯報錯，導致整個 DOM 樹崩解（白畫面）。
*   **全域 Error Boundary：** 放在 App 的最上層，當遇到無法恢復的毀滅性錯誤時，展示「糟糕，系統異常」並提供「重新整理」按鈕的 Fallback UI。
*   **局部 Error Boundary：** 針對高風險或外部依賴的區塊（如：廣告區塊、第三方圖表），使用獨立的 Error Boundary 包裹。若圖表壞掉，只有圖表區顯示「載入失敗」，而不影響結帳或側邊欄等主畫面的獨立運作。

### 實作方案建議 (以 React 為例)
不建議每次專案都徒手撰寫笨重的 Class Component。強烈建立統一引入輕量套件 `react-error-boundary` 進行攔截：

```jsx
import { ErrorBoundary } from 'react-error-boundary';

// 定義崩潰時要展示的備用畫面 (Fallback UI)
function GlobalFallback({ error, resetErrorBoundary }) {
  return (
    <div className="error-container p-4 bg-red-50">
      <h3>頁面發生未預期錯誤</h3>
      <p>{error.message}</p>
      <button onClick={resetErrorBoundary}>再試一次</button>
    </div>
  );
}

// 在核心元件外層套上防護罩
function App() {
  return (
    <ErrorBoundary FallbackComponent={GlobalFallback}>
       <AppDashboard />
    </ErrorBoundary>
  );
}
```

## 4. 防呆與重試機制 (Retry & Fallback)

*   在發送刪除、付款等毀滅性或不可逆的 API 時，必須實作防連點 (Debounce / 按鈕 Disable 狀態)。
*   非破壞性的資料獲取（如：拉取商品清單），可利用如 React Query/SWR 自帶的機制，設定失敗重試次數 (Retries)，增加網路閃斷時的成功率。
