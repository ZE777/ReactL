# 前端資安防護守則 (Frontend Security Guide)

許多開發者誤以為「資安是後端的事」，但前端是防衛使用者的第一線。未遵守以下原則，將可能導致嚴重的資料外洩或帳號劫持。

## 1. 跨站腳本攻擊防禦 (XSS - Cross-Site Scripting)
這是前端最常見的攻擊，攻擊者在你的網頁注入惡意 JavaScript 腳本。
*   **嚴禁原生 HTML 渲染：** 除非必要，絕對避免使用 `dangerouslySetInnerHTML` (React) 或 `v-html` (Vue)。
*   **強制消毒 (Sanitization)：** 若因為富文本編輯器 (Rich-text editor) 必須渲染來自資料庫的 HTML 字串，**必須**強制先經過 `DOMPurify.sanitize(htmlString)` 清洗，濾除 `<script>` 標籤或不安全的 `onClick` 屬性後，才可以渲染到畫面上。

## 2. 跨站請求偽造防禦 (CSRF - Cross-Site Request Forgery)
雖然這主要靠後端防禦，但前端必須配合：
*   **Cookie 驗證機制：** 確認與後端的 API 溝通是否依賴 Cookie。如果是，確保後端有設定 `SameSite=Strict` 或 `Lax`。
*   **CSRF Token：** 若有使用 CSRF Token 機制，前端攔截器必須在每個 POST/PUT/DELETE 請求中，動態夾帶 `X-CSRF-Token` 在 Header 中。

## 3. 機敏資訊與 Token 儲存安全
*   **Token 存放：** 高度敏感的 JWT Access Token，不要毫無防備地存在 `localStorage`，因為任何 XSS 腳本都能輕易讀取。較佳的安全實踐請後端設定 **HttpOnly Secure Cookie**，讓前端 JS 完全碰不到真實 Token，卻能在發送 Request 時由瀏覽器自動帶上。
*   **避免 PII 外洩於網址列：** 任何具備個人識別特徵 (Personally Identifiable Information) 的資料（身分證字號、金鑰、密碼），絕對不可以出現在 URL 參數 `?token=1234` 中，因為這會被記錄在瀏覽器瀏覽紀錄及代理伺服器日誌中。

## 4. 內容安全政策 (CSP - Content Security Policy)

> ⚠️ **CSP 為必要安全措施，非可選項目。** 所有對外官網與內部後台皆必須實作 CSP 標頭。

CSP 是攔截 XSS 攻擊的終極防護網。**必須**由伺服器端派發 HTTP Header（優於 `<meta>` 標籤，因為 `<meta>` 無法設定 `frame-ancestors` 等指令）。

### 必要的 CSP Directives

```
default-src 'self';
script-src 'self' 'nonce-{動態隨機值}';
style-src 'self' 'unsafe-inline';
img-src 'self' https://cdn.example.com data:;
font-src 'self';
connect-src 'self' https://api.example.com;
frame-ancestors 'none';
base-uri 'self';
form-action 'self';
```

**各指令說明：**
| Directive | 用途 | 備註 |
|-----------|------|------|
| `default-src 'self'` | 預設僅允許同源資源 | 所有未明確設定的指令繼承此值 |
| `script-src 'nonce-{}'` | 腳本必須帶 nonce 才能執行 | **禁止使用 `'unsafe-eval'`**，避免 `eval()` 攻擊面 |
| `frame-ancestors 'none'` | 禁止本站被嵌入 iframe | 防禦 Clickjacking 攻擊 |
| `connect-src` | 限制 XHR/fetch 可連線的域名 | 僅列白名單 API 域名 |
| `base-uri 'self'` | 防止 `<base>` 標籤劫持 | 阻止攻擊者透過注入 `<base>` 竄改相對路徑 |

### Next.js App Router 的 CSP 實作方式

```typescript
// middleware.ts — 動態注入 nonce，確保每次請求產生不同值
// 注意：Next.js middleware 預設在 Edge Runtime 執行，不支援 Node.js crypto 模組，
// 必須使用 Web Crypto API。
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const array = new Uint8Array(16);
  crypto.getRandomValues(array);
  const nonce = btoa(String.fromCharCode(...array));
  const cspHeader = `
    default-src 'self';
    script-src 'self' 'nonce-${nonce}';
    style-src 'self' 'unsafe-inline';
    img-src 'self' https://cdn.example.com data:;
    font-src 'self';
    connect-src 'self' https://api.example.com;
    frame-ancestors 'none';
    base-uri 'self';
    form-action 'self';
  `.replace(/\n/g, '');

  const response = NextResponse.next();
  response.headers.set('Content-Security-Policy', cspHeader);
  // 將 nonce 傳遞至 Server Component
  response.headers.set('x-nonce', nonce);
  return response;
}
```
