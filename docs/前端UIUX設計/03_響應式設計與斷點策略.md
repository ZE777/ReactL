# 響應式設計與斷點策略 (Responsive Design & Breakpoint Strategy)

本文件定義專案的響應式設計系統，涵蓋斷點定義、Grid 佈局、元件適應行為與觸控優化。採用 **Mobile-First** 原則，以最小螢幕為基準逐步增強。

## 1. 斷點定義 (Breakpoint Definitions)

### 1.1 系統斷點

基於內容需求而非特定裝置，與 Tailwind CSS 預設相容：

| Tailwind Prefix | 斷點值 | 對應情境 | 典型裝置 |
|-----------------|--------|----------|----------|
| （預設） | 0~639px | 手機直向 | iPhone SE ~ iPhone 15 Pro Max |
| `sm:` | ≥ 640px | 大手機 / 小平板 | iPhone Pro Max 橫向、iPad Mini |
| `md:` | ≥ 768px | 平板直向 | iPad、Surface Go |
| `lg:` | ≥ 1024px | 平板橫向 / 小筆電 | iPad Pro 橫向、13" 筆電 |
| `xl:` | ≥ 1280px | 桌面 | 一般桌面螢幕 |
| `2xl:` | ≥ 1536px | 大螢幕 | 27" 以上顯示器 |

### 1.2 使用原則

*   **Mobile-First：** CSS 預設撰寫手機樣式，使用 `sm:`, `md:`, `lg:` 逐步增強
    ```html
    <!-- ✅ 正確 — Mobile-First -->
    <div class="flex flex-col md:flex-row lg:gap-8">

    <!-- ❌ 錯誤 — Desktop-First（使用 max-width） -->
    <div class="flex flex-row max-md:flex-col">
    ```
*   **禁止自定義斷點：** 不可使用 `min-[840px]:` 等任意斷點值，必須使用系統定義的六個斷點
*   **容器查詢 (Container Query)：** 元件級別的響應式行為優先使用 `@container`，減少對視窗寬度的依賴

## 2. Grid 佈局系統 (Grid Layout System)

### 2.1 頁面 Grid

| 斷點 | 欄數 | Gutter | 頁面邊距 | 最大寬度 |
|------|------|--------|----------|----------|
| Mobile（< 640px） | 4 欄 | 16px | 16px | 100% |
| sm（≥ 640px） | 6 欄 | 16px | 24px | 640px |
| md（≥ 768px） | 8 欄 | 24px | 32px | 768px |
| lg（≥ 1024px） | 12 欄 | 24px | 32px | 1024px |
| xl（≥ 1280px） | 12 欄 | 32px | auto | 1280px |
| 2xl（≥ 1536px） | 12 欄 | 32px | auto | 1440px |

### 2.2 Tailwind Grid 對應

```html
<!-- 頁面容器 -->
<div class="mx-auto px-4 sm:px-6 lg:px-8 max-w-7xl">
  
  <!-- 標準 Grid -->
  <div class="grid grid-cols-4 sm:grid-cols-6 md:grid-cols-8 lg:grid-cols-12 gap-4 lg:gap-6 xl:gap-8">
    <!-- Grid Items -->
  </div>
</div>
```

### 2.3 常見佈局模式

**卡片列表 (Card Grid)：**
```html
<!-- 手機 1 欄 → 平板 2 欄 → 桌面 3~4 欄 -->
<div class="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4 gap-4 lg:gap-6">
  <Card />
</div>
```

**側邊欄佈局 (Sidebar Layout)：**
```html
<!-- 手機：sidebar 隱藏 → 桌面：sidebar + content -->
<div class="lg:grid lg:grid-cols-[280px_1fr] lg:gap-8">
  <aside class="hidden lg:block">Sidebar</aside>
  <main>Content</main>
</div>
```

**表單佈局 (Form Layout)：**
```html
<!-- 手機：堆疊 → 桌面：雙欄 -->
<form class="grid grid-cols-1 md:grid-cols-2 gap-4 md:gap-6">
  <div class="md:col-span-2">Full width field</div>
  <div>Half width field</div>
  <div>Half width field</div>
</form>
```

## 3. 元件響應式行為 (Component Responsive Behavior)

### 3.1 導覽列 (Navigation)

| 斷點 | 行為 |
|------|------|
| Mobile（< lg） | 漢堡選單 (Hamburger Menu)，點擊展開側拉式導覽 (Drawer) |
| lg+ | 完整水平導覽列，所有項目直接可見 |

*   漢堡選單按鈕必須有 `aria-label="開啟選單"` 與 `aria-expanded` 狀態
*   展開時實作 Focus Trap，按 Escape 可關閉

### 3.2 表格 (Data Table)

表格在小螢幕上的處理是 RWD 的常見難題，依資料特性選擇策略：

| 策略 | 適用情境 | 實作方式 |
|------|----------|----------|
| 水平捲動 | 欄位不多（< 8 欄）、數據對比需求高 | `overflow-x-auto` + 固定首欄 |
| 卡片化 | 欄位多、手機操作頻繁 | `< md` 時將每列轉為卡片排列 |
| 隱藏次要欄位 | 有明確的主要/次要欄位區分 | `hidden md:table-cell` 隱藏次要欄位 |
| 展開列 | 欄位很多但不常全部查看 | 預設顯示關鍵欄位，點擊展開完整資料 |

```html
<!-- 卡片化策略範例 -->
<div class="hidden md:block">
  <table><!-- 桌面：標準表格 --></table>
</div>
<div class="md:hidden space-y-4">
  <!-- 手機：卡片列表 -->
  <div class="rounded-lg border p-4">
    <h3 class="font-semibold">車輛名稱</h3>
    <dl class="mt-2 space-y-1 text-body-sm">
      <div class="flex justify-between">
        <dt class="text-neutral-500">狀態</dt>
        <dd>可租借</dd>
      </div>
    </dl>
  </div>
</div>
```

### 3.3 Modal 與 Drawer

| 斷點 | Modal 行為 | Drawer 行為 |
|------|-----------|-------------|
| Mobile（< md） | 全螢幕顯示（`fixed inset-0`） | 從底部滑入（Bottom Sheet） |
| md+ | 居中浮層（`max-w-lg mx-auto`） | 從右側滑入 |

### 3.4 按鈕與操作列

*   **手機：** 主要操作按鈕固定於螢幕底部（Sticky Bottom Bar）
*   **桌面：** 按鈕依據語境放置（表單底部、表格列末端、頁面頂部）
*   **Icon-only 按鈕：** 僅桌面允許，手機必須顯示文字標籤或至少提供 `aria-label`

## 4. 觸控優化 (Touch Optimization)

### 4.1 觸控目標尺寸

根據 WCAG 2.5.8 (Target Size)：

| 元素類型 | 最小觸控區域 | Tailwind 對應 |
|----------|-------------|---------------|
| 按鈕 | 44 × 44px | `min-h-11 min-w-11`（44px = 2.75rem） |
| 圖示按鈕 | 44 × 44px | `p-2.5`（含 padding 達 44px） |
| 列表項目 | 高度 ≥ 44px | `min-h-11 py-3` |
| Checkbox / Radio | 44 × 44px（含點擊區域） | Label 可點擊，擴大 hit area |

### 4.2 觸控手勢

*   **Swipe：** 僅用於輪播 (Carousel) 與刪除確認（左滑刪除），不可作為唯一操作方式
*   **Long Press：** 不可作為主要操作，僅作為輔助（如長按預覽）
*   **Pinch/Zoom：** 不可禁用瀏覽器原生的 pinch-to-zoom（`<meta name="viewport">` 禁止設定 `user-scalable=no`）

### 4.3 間距防誤觸

*   互動元素之間的間距至少 `8px`（`gap-2`），避免誤觸相鄰按鈕
*   刪除/危險操作按鈕應與一般按鈕保持更大間距

## 5. 內容優先級策略 (Content Priority)

### 5.1 各斷點內容處理

並非所有內容都需要在所有裝置上顯示。依內容優先級定義裁減策略：

| 優先級 | 說明 | 手機 | 平板 | 桌面 |
|--------|------|------|------|------|
| P0 — 核心 | 使用者完成任務必需的資訊 | ✅ 顯示 | ✅ 顯示 | ✅ 顯示 |
| P1 — 重要 | 增強理解但非必要的資訊 | ✅ 簡化顯示 | ✅ 顯示 | ✅ 顯示 |
| P2 — 輔助 | 提供額外細節的資訊 | 🔽 摺疊/隱藏 | ✅ 顯示 | ✅ 顯示 |
| P3 — 裝飾 | 裝飾性或次要功能 | ❌ 隱藏 | 🔽 簡化 | ✅ 顯示 |

### 5.2 隱藏策略

```html
<!-- P2 內容 — 手機隱藏，平板以上顯示 -->
<p class="hidden md:block text-neutral-500">補充說明文字...</p>

<!-- P1 內容 — 手機簡化顯示 -->
<span class="md:hidden">NT$1,200/日</span>
<span class="hidden md:inline">每日租金：NT$1,200（含保險）</span>

<!-- P2 內容 — 手機以摺疊方式呈現 -->
<details class="md:hidden">
  <summary>查看更多規格</summary>
  <div>完整規格內容...</div>
</details>
```

## 6. 圖片與媒體響應式 (Responsive Media)

### 6.1 響應式圖片

```tsx
// 使用 next/image 的響應式圖片
import Image from 'next/image';

<Image
  src="/vehicle.jpg"
  alt="Toyota Camry 側面照"
  sizes="(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 33vw"
  fill
  className="object-cover"
  priority  // 首屏圖片加上 priority
/>
```

### 6.2 Art Direction（藝術指導）

不同螢幕尺寸可能需要不同裁切或構圖的圖片：

```html
<picture>
  <source media="(min-width: 1024px)" srcset="/hero-desktop.jpg" />
  <source media="(min-width: 640px)" srcset="/hero-tablet.jpg" />
  <img src="/hero-mobile.jpg" alt="品牌主視覺" />
</picture>
```

## 7. 公開網站 vs 後台管理介面的差異

| 面向 | 公開網站 (Next.js) | 後台管理介面 (React SPA) |
|------|-------------------|------------------------|
| 主要裝置 | 手機 > 平板 > 桌面 | 桌面 > 平板 > 手機 |
| Mobile-First 程度 | 嚴格執行 | 可適度放寬（Desktop-First 亦可接受） |
| 觸控優化 | 必要 | 次要（桌面為主） |
| 內容密度 | 低密度、大留白 | 高密度、緊湊佈局可接受 |
| 表格策略 | 卡片化為主 | 水平捲動 + 固定欄為主 |
| 導覽 | 漢堡選單 | 可收合側邊欄 (Collapsible Sidebar) |

## 8. 測試檢核 (Testing Checklist)

每次版本發佈前，至少在以下視窗寬度下驗證：

- [ ] **375px** — iPhone SE（最小主流手機）
- [ ] **390px** — iPhone 14/15 標準
- [ ] **768px** — iPad 直向
- [ ] **1024px** — iPad 橫向
- [ ] **1280px** — 標準桌面
- [ ] **1920px** — Full HD 桌面

額外檢查：
- [ ] 瀏覽器視窗從 320px 拖曳至 1920px，佈局無斷裂或重疊
- [ ] 文字放大 200%（browser zoom）後佈局正常
- [ ] 橫向/直向旋轉後佈局正確適應
