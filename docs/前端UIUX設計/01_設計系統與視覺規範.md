# 設計系統與視覺規範 (Design System & Visual Guidelines)

本文件定義專案的統一視覺語言，確保公開網站（Next.js）與後台管理介面（React SPA）的 UI 呈現一致且可維護。所有 Design Tokens 必須定義於此，並直接對應至 `tailwind.config.js`。

## 1. 色彩系統 (Color System)

### 1.1 色彩架構

專案色彩分為五個層級，每個層級有明確的語意用途：

| 層級 | 用途 | Tailwind Token 前綴 |
|------|------|---------------------|
| Primary | 品牌主色，用於主要 CTA、品牌識別 | `brand-primary-*` |
| Secondary | 輔助色，用於次要操作、標記 | `brand-secondary-*` |
| Neutral | 灰階，用於文字、背景、邊框、分隔線 | `neutral-*` |
| Semantic | 狀態色，用於成功/警告/錯誤/資訊 | `status-*` |
| Surface | 背景層級，用於卡片、疊層、遮罩 | `surface-*` |

### 1.2 色階定義

每個色彩需定義完整的 50~950 色階：

```js
// tailwind.config.js — theme.extend.colors
colors: {
  'brand-primary': {
    50:  '#f0f7ff',  // 極淺背景 / Hover 背景
    100: '#e0efff',  // 淺色背景 / Selected 狀態
    200: '#b9dfff',  // 輕量裝飾 / Tag 背景
    300: '#7cc4ff',  // 次要元素
    400: '#36a9ff',  // 較淡的互動色
    500: '#0d8fff',  // ← 品牌主色基準值
    600: '#0070e0',  // Hover 加深
    700: '#0058b5',  // Active 加深
    800: '#004a95',  // 深色文字配色
    900: '#003d7a',  // 極深色
    950: '#002750',  // 最深色 / Dark Mode 用
  },
  'neutral': {
    50:  '#fafafa',
    100: '#f5f5f5',
    200: '#e5e5e5',
    300: '#d4d4d4',
    400: '#a3a3a3',
    500: '#737373',
    600: '#525252',
    700: '#404040',
    800: '#262626',
    900: '#171717',
    950: '#0a0a0a',
  },
  'status-success': { light: '#ecfdf5', DEFAULT: '#10b981', dark: '#065f46' },
  'status-warning': { light: '#fffbeb', DEFAULT: '#f59e0b', dark: '#92400e' },
  'status-error':   { light: '#fef2f2', DEFAULT: '#ef4444', dark: '#991b1b' },
  'status-info':    { light: '#eff6ff', DEFAULT: '#3b82f6', dark: '#1e40af' },
  'surface': {
    base:    '#ffffff',   // 頁面底色
    raised:  '#f9fafb',   // 卡片、區塊背景
    overlay: 'rgba(0,0,0,0.5)', // Modal 遮罩
  },
}
```

### 1.3 色彩使用規則

*   **禁止寫死色號：** 不可出現 `text-[#1a2b3c]` 或 `bg-[#f0f0f0]`，一律使用語意化 Token
*   **語意優先於外觀：** 使用 `text-status-error` 而非 `text-red-500`，確保全站更換色彩時只需修改一處
*   **色彩無障礙：** 文字色與背景色的對比度必須符合 WCAG AA 標準（一般文字 ≥ 4.5:1 / 大字 ≥ 3:1）
*   **不依賴顏色傳達資訊：** 錯誤狀態除了紅色還需搭配圖示（如 ⚠️）或文字說明

## 2. 字型系統 (Typography System)

### 2.1 字型家族 (Font Family)

```js
// tailwind.config.js — theme.extend.fontFamily
fontFamily: {
  heading: ['Noto Sans TC', 'Inter', 'system-ui', 'sans-serif'],
  body:    ['Noto Sans TC', 'Inter', 'system-ui', 'sans-serif'],
  mono:    ['JetBrains Mono', 'Fira Code', 'monospace'],
}
```

> **注意：** 使用 `next/font` 載入字型以避免 FOIT/FOUT 問題，並確保最佳 CLS 表現。

### 2.2 字級 (Type Scale)

基於 **1.25 Modular Scale (Major Third)**，以 `16px` 為基準值：

| Token | 大小 | 行高 | 字重 | 用途 |
|-------|------|------|------|------|
| `text-display` | 36px / 2.25rem | 1.2 | Bold (700) | 英雄區塊標題 |
| `text-h1` | 30px / 1.875rem | 1.25 | Bold (700) | 頁面主標題 |
| `text-h2` | 24px / 1.5rem | 1.3 | Semibold (600) | 區塊標題 |
| `text-h3` | 20px / 1.25rem | 1.35 | Semibold (600) | 子區塊標題 |
| `text-h4` | 18px / 1.125rem | 1.4 | Medium (500) | 卡片標題 |
| `text-body-lg` | 18px / 1.125rem | 1.75 | Regular (400) | 大型內文 |
| `text-body` | 16px / 1rem | 1.625 | Regular (400) | 預設內文 |
| `text-body-sm` | 14px / 0.875rem | 1.5 | Regular (400) | 輔助文字、表格內容 |
| `text-caption` | 12px / 0.75rem | 1.5 | Regular (400) | 標籤、時間戳記 |
| `text-overline` | 11px / 0.6875rem | 1.5 | Medium (500) | 分類標籤、全大寫標注 |

### 2.3 字型使用規則

*   **最小字級：** 正式內容不可小於 `12px`，互動元素文字不可小於 `14px`
*   **行高原則：** 標題行高 1.2~1.4 / 內文行高 1.5~1.75 / 單行元素（按鈕、標籤）行高 1
*   **字重限制：** 僅使用 Regular(400)、Medium(500)、Semibold(600)、Bold(700) 四種，避免視覺混亂
*   **段落寬度：** 最佳閱讀寬度為 60~80 字元（中文約 30~40 字），使用 `max-w-prose` 限制

## 3. 間距系統 (Spacing System)

### 3.1 基於 4px Grid 的間距定義

所有間距必須是 4px 的倍數，與 Tailwind 預設相容：

| Token | 數值 | Tailwind Class | 典型用途 |
|-------|------|---------------|---------|
| `spacing-0.5` | 2px | `p-0.5` | 微間距（圖示與文字間） |
| `spacing-1` | 4px | `p-1` | 極小間距 |
| `spacing-2` | 8px | `p-2` | 元素內部緊湊間距 |
| `spacing-3` | 12px | `p-3` | 元素內部標準間距 |
| `spacing-4` | 16px | `p-4` | 卡片內距、欄位間距 |
| `spacing-5` | 20px | `p-5` | 區塊內距 |
| `spacing-6` | 24px | `p-6` | 大區塊內距 |
| `spacing-8` | 32px | `p-8` | 區塊之間的間距 |
| `spacing-10` | 40px | `p-10` | 大區塊之間的間距 |
| `spacing-12` | 48px | `p-12` | Section 之間的間距 |
| `spacing-16` | 64px | `p-16` | Page Section 間距 |

### 3.2 間距使用規則

*   **禁止任意數值：** 不可出現 `mt-[13px]` 或 `gap-[7px]`，必須使用系統內的間距 Token
*   **一致的內距/外距：** 同類型的元件（如所有卡片）必須使用相同的 padding/margin 值
*   **垂直韻律 (Vertical Rhythm)：** 區塊之間的垂直間距應隨層級遞增 — 元素間 `spacing-2~4` / 群組間 `spacing-6~8` / Section 間 `spacing-12~16`

## 4. 圓角與陰影 (Border Radius & Shadows)

### 4.1 圓角系統

```js
// tailwind.config.js — theme.extend.borderRadius
borderRadius: {
  'none': '0',
  'sm':   '4px',    // 輸入框、小標籤
  'md':   '8px',    // 按鈕、卡片
  'lg':   '12px',   // 大卡片、對話框
  'xl':   '16px',   // Hero 區塊
  'full': '9999px', // 頭像、圓形按鈕
}
```

### 4.2 陰影系統（Elevation）

```js
// tailwind.config.js — theme.extend.boxShadow
boxShadow: {
  'elevation-1': '0 1px 2px rgba(0,0,0,0.05)',                           // 卡片預設
  'elevation-2': '0 4px 6px -1px rgba(0,0,0,0.07)',                      // 卡片 Hover
  'elevation-3': '0 10px 15px -3px rgba(0,0,0,0.08)',                    // Dropdown / Popover
  'elevation-4': '0 20px 25px -5px rgba(0,0,0,0.1)',                     // Modal / Dialog
  'elevation-5': '0 25px 50px -12px rgba(0,0,0,0.15)',                   // Toast / Notification
}
```

## 5. 動畫與過渡 (Animation & Transitions)

### 5.1 統一過渡時間

```css
:root {
  --duration-instant:  75ms;    /* 即時回饋（如 Checkbox toggle） */
  --duration-fast:     150ms;   /* 快速過渡（如 Hover 色彩變化） */
  --duration-normal:   250ms;   /* 標準過渡（如 Dropdown 展開） */
  --duration-slow:     350ms;   /* 緩慢過渡（如 Modal 淡入） */
  --duration-slower:   500ms;   /* 頁面切換過渡 */

  --easing-default:    cubic-bezier(0.25, 0.8, 0.25, 1);   /* 通用緩動 */
  --easing-enter:      cubic-bezier(0, 0, 0.2, 1);         /* 進入 */
  --easing-exit:       cubic-bezier(0.4, 0, 1, 1);         /* 離開 */
  --easing-bounce:     cubic-bezier(0.34, 1.56, 0.64, 1);  /* 彈跳效果 */
}
```

### 5.2 動畫使用規則

*   **效能優先：** 僅動畫 `transform` 與 `opacity`，禁止動畫 `width`、`height`、`margin`、`top/left`
*   **尊重使用者偏好：** 所有動畫必須包裹在 `@media (prefers-reduced-motion: no-preference)` 中
*   **有目的性：** 動畫用於引導注意力或提供操作回饋，非裝飾用途

## 6. 圖示系統 (Iconography)

### 6.1 圖示規範

*   **統一圖示庫：** 全專案使用 **Lucide Icons**（與 shadcn/ui 相容）
*   **尺寸規範：**
    *   `16px` — 行內小圖示（如狀態指示器）
    *   `20px` — 標準圖示（如按鈕圖示、表格操作）
    *   `24px` — 導覽列圖示、卡片圖示
    *   `32px+` — 裝飾性大圖示（如空狀態插圖）
*   **Stroke Width：** 統一使用 `strokeWidth={1.5}`（Lucide 預設為 2，稍顯粗重）
*   **無障礙：** 功能性圖示必須搭配 `aria-label`；裝飾性圖示使用 `aria-hidden="true"`

## 7. Dark Mode 策略

> **實作現況（2026-06-05）：** §1–§6 為跨前後台的設計語言「目標規格」（以 `brand-primary` CSS Custom Properties 為主，對應公開網站 Next.js）。  
> 後台管理介面（`prompt-studio-admin`，Vite SPA）**已完整實作 Dark Mode**，採用較務實的語意化色系 token 層（見 §8），並非以本節的 CSS 變數方案實作。兩者目標一致、實作途徑不同。

設計系統預留的擴展原則：

*   公開網站色彩使用 CSS Custom Properties 定義，切換 Dark Mode 只需替換變數值
*   Tailwind 的 `dark:` variant 已啟用，後台已逐元件套用暗色變體（`dark:bg-zinc-*` 等）
*   Surface 層級色彩在 Dark Mode 下的對應：`base → #0a0a0a` / `raised → #171717` / `overlay → rgba(0,0,0,0.7)`

## 8. 後台實作現況：Design Token 層與共用 UI 元件庫

> 對象：`prompt-studio-admin`（Vite + React + Tailwind）。本節記錄目前**已落地**的設計系統實作，與 §1–§6 的目標規格並存。

### 8.1 語意化色彩 Token（`src/tokens/colors.ts`）

後台不採 `brand-primary-*` 數字色階，而是定義一組**語意化顏色 key** 與三組對照 map，所有接受 `color` prop 的元件共用，並內建 light / dark 兩套 class：

```ts
export type Color = 'violet' | 'slate' | 'green' | 'red' | 'amber' | 'blue'

softColorMap   // 柔色系：bg-50 底 + text-600 文字（Tag 使用）
badgeColorMap  // 中色系：bg-100 底 + text-700 文字（Badge 使用）
iconColorMap   // 圖示按鈕：半透明底 + 圖示色 + hover（IconButton 使用）
```

*   每個 key 都同時定義 `dark:` 變體（如 `violet: 'bg-violet-50 dark:bg-violet-900/30 text-violet-600 dark:text-violet-400'`），故 Dark Mode 為色系內建、非額外覆寫。
*   元件若需特例，可在本地 spread 後覆蓋單一條目：`{ ...badgeColorMap, slate: '自訂' }`。
*   主互動色統一為 **violet**（品牌主色），中性色為 **slate（light）/ zinc（dark）**。

### 8.2 共用 UI 元件清單（`src/components/ui/`）

| 元件 | 用途 | 主要 props |
|------|------|-----------|
| `Card` | 統一卡片容器（白/zinc-900 底、border、rounded-xl）| `className` |
| `Badge` | 中色系狀態徽章（圓角膠囊）| `color: Color`、`size: 'sm' \| 'md'` |
| `Tag` | 柔色系小標籤（含 border）| `color: Color` |
| `Button` | 主要按鈕，含 loading spinner | `variant: primary \| secondary \| ghost \| danger \| danger-ghost \| blue`、`size: sm \| md \| icon`、`loading` |
| `GhostButton` | 低強度文字按鈕（工具列、次要操作）| `onClick`、`disabled` |
| `IconButton` | 7×7 圖示按鈕，套 `iconColorMap` | `color: Color`、`aria-label` |
| `SegmentedControl` | 分段切換（白底 / violet 填色兩種 active 風格）| `options`、`value`、`onChange`、`variant: default \| accent` |
| `FilterPill` | 圓角篩選膠囊（列表分類篩選）| `active`、`onClick` |
| `DropdownSelect` | 統一下拉選單；支援平坦 / 分組選項、subLabel、彩色 badge、`fixed` 定位避免被裁切、鍵盤/點擊外關閉、`role=listbox/option` 無障礙 | `value`、`onChange`、`options` 或 `groups`、`loading`、`hasError` |
| `PageHeader` | 頁面標題 + 副標 | `title`、`subtitle` |
| `settingsUi` | 設定頁組合：`Section`（卡片區塊）、`FieldRow`（左標題右內容列）、`EyeIcon`（金鑰顯示/隱藏）| — |

> 元件一律以 `color: Color` 對應 §8.1 token，不直接寫死 Tailwind 色號，符合 §1.3「語意優先於外觀」。

### 8.3 表單輔助（`src/lib/form.ts`）

針對 token / secret / 密碼等**不可含空白**的敏感欄位，包裝 react-hook-form 的 `register`：

*   `noSpace(register(...))`：`onChange` 階段即時濾除所有空白字元（按空白鍵不產生、貼上含空白自動清除）。
*   `useNoSpace(clearMs)`：同上，且空白被擋掉時對該欄位回傳「不可輸入空白」即時紅字提示，`clearMs` 後自動消失。

### 8.4 與目標規格的差異備忘

| 項目 | §1–§6 目標規格 | 後台實作現況 |
|------|---------------|-------------|
| 色彩 token | `brand-primary-*` 數字色階 + CSS 變數 | 語意化 `Color` 型別 + 三組 colorMap（TS 模組）|
| Dark Mode | 預留（CSS 變數替換）| 已完整實作（色系內建 `dark:` 變體）|
| 元件來源 | shadcn/ui + Radix | 自建輕量元件（無 Radix 相依）|

> 後續若整合公開網站，再評估是否將兩套色彩系統收斂為單一 token 來源。
